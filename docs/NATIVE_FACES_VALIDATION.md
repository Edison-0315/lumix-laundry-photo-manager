# 自动人物分类增量验证

2026-11-04，Apple Silicon / 当前 macOS，P7 基础已接通，完整软件尚未完成。

## 实现

- SwiftUI 整理菜单按当前活动启动；本机 YuNet 检测、SFace 对齐与 float32 向量，沿用原规则：.40/.55 相似度与 .05 歧义间隔；过滤低置信度、小脸和相对背景脸。
- 人工人物归属跳过；自动分入普通人物、合影、未分类。复用本机库文件事务，支持进度、取消、逐照片错误及结果报告，已完成照片保留结果。
- 内嵌 NumPy 2.5.4、OpenCV headless 4.13.0.92、rawpy 0.27.1；模型摘要固定并随 app 打包，YuNet MIT 与 SFace Apache 许可证保留。
- JPEG/RAW 解码通过 no-follow 文件描述符；分类不上传照片或向量，不写来源文件。

## 本轮证据

- `test_faces.py` 5 个新增用例已通过：规则/归一化、人工归属及已修状态保留、取消后已完成组保留、符号链接拒读、真模型与错误模型拒绝、同人/双人/无脸分类。最后增补阈值和取消断言后，只重跑受影响 2 项；没有重跑既有业务套件。
- 公开固定人像检测到 1 张脸，框约 `[207.7856,182.5317,145.9389,206.92]`，128 维 float32 单位向量；样本摘要见 `macos/BackendTests/face-sample.json`，样本只存于忽略的 build/。
- 授权的 DC-S5M2 RW2 完成解码及推理，检测数为 0；原文件摘要和修改时间不变。这不是人脸阳性样本。
- Debug app 编译后，实际界面打开隔离测试库 `NativeFaces`，活动 `Faces-056687e4` 经整理菜单与确认执行，报告显示“整理 4 张照片 · 跳过 1 张”。
- 将新 app 复制至临时中文/空格路径，`codesign --verify --deep --strict` 通过；内嵌 157 个 Mach-O 均为 arm64。PATH/PYTHONHOME/PYTHONPATH 指向不存在目录时，内置解释器仍成功载入 NumPy/OpenCV/rawpy、校验模型并检测公开人像 1 张脸。
- 此前打开库和展开菜单的 CUA 操作曾超时，后续重新获取界面即可继续；进程采样中 app 事件循环与 helper 等待输入。未据此修改业务代码，也不把自动化超时判为已确认的 app 死锁。
