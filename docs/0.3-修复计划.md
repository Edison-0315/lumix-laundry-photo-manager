# 片集 0.3 实现计划

使用 writing-plans 与 executing-plans，在现有 feature/photo-manager 分支内联实现。
规格依据：用户本轮四项反馈；保留既有 SD 选片、多选、关联成片与本地 Photoshop 工作流。

## 目标与边界

- JPEG / RAW 可独立读取与筛选。识别同一拍摄目录下 JPEG/JPG 与 RAW/RW2 格式子目录中的唯一同名配对；其他目录不凭文件名强行合并。
- 同一扫描中先导入 JPEG 再补 RAW，保留同一照片关联；错误或有歧义的文件不影响其他照片。
- 右键保留已选组，对未选照片右键则选择该张；命令遵守当前视图与忙碌状态。底部收起次要按钮，保留“更多操作”入口和键盘入口。
- 应用内照片库管理：命名新建、选择父目录、打开已有库、最近照片库、移除最近记录。任务中不能切换。
- 库内删除移入可恢复的回收站，整组 JPEG / RAW / XMP / 成片及保留版本一同处理，SD 来源不删除；缺失文件不阻止删除已有文件，恢复不覆盖同名文件。

## 文件与任务

1. discovery.py / bridge.py / library.py / store.js：分目录配对、多个来源目录、格式筛选及分次导入。先补 discovery / library 回归测试并确认失败，再实现并验证。
2. catalog.py / library.py / bridge.py：日志保护的删除、回收站列表、恢复。先验证完整文件组、占用回滚、缺失、重导入与同名恢复测试失败，再实现并验证。
3. bridge.py / library-manager.js：受原生目录授权约束的新建与最近照片库。先验证取消、同名拒绝、来源重叠、重启与切换测试失败，再实现并验证。
4. context-menu.js / dialogs.js / app.js / index.html / app.css：右键、更多操作、删除确认、恢复入口、管理照片库。使用真实浏览器交互回归，覆盖多选、菜单关闭、键盘、格式与建库流程。
5. 独立整体审查、完整 pytest / 浏览器 / 原生 WebView2 验证，更新说明，构建 0.3 便携包及源码包。

## 审查重点

- 同名不同目录照片不误配；只扫描一种格式也能读。
- 移动失败、取消与预览占用时文件及数据库一致。
- 删除和恢复都不碰 SD 来源，不覆盖库内现有文件。
- 切库后不沿用旧库选择和预览，首次导入取消建库保留选片。
- 恢复人物已改名/已合并的照片时，仍有有效人物与目录；回收站照片不参与自动识别和正常归档。
