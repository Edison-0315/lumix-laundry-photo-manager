# 照片管理器模块化实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 executing-plans 逐任务实现此计划。

**目标：** 将集中式入口拆为职责明确、可单独查看和验证的模块，保持 0.12 行为。

**架构：** 前端以回调组合控制器和渲染器，保留 store.js/dialogs.js 兼容导出。后端用显式函数服务与 Library 门面共享同一库上下文，事务与锁仍由原实现持有。

**技术栈：** Python 3.12、SQLite、pywebview/WebView2、原生 ES modules、CSS。

**规格：** docs/superpowers/specs/2026-11-01-modules.md

## 全局约束

- 界面、交互、公开桥接方法及 .片集 格式不变。
- SD 只读、导入复制、回收站和删除边界遵循 AGENTS.md。
- 新工作区为独立本地克隆，旧源码和版本保留，不推送。
- 不添加 UI 框架、状态库、运行时依赖或第二套事务机制。

## 审查重点（Review Focus）

- JPEG/RAW 分步补充后仍保持原有分组、人物和成片关联。
- 任务失败/取消后恢复按钮，保留上次扫描与选择，不发布半次扫描。
- 人物、活动删除与恢复仍经同一日志和锁，不丢失缺失文件与回收站关联。
- ES module 拆分不能形成导入环或多个状态实例，迟到预览不能覆盖新照片。
- 打包后子目录模块、模型和资源必须存在，中文路径下可正常启动。
