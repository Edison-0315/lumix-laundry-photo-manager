# 文件和数据库替换边界增量

2026-11-05，继续 P3/P6 文件安全收尾。本轮仅覆盖新增故障时序及实际受改动影响的部分。

## 改动

- SQLite 连接打开后、事务提交前重新核验库、数据库和锁身份。持久的名称替换会使事务停止或回滚，不继续写替换数据库。
- 复制和移动前后核验已持有父目录描述符是否仍对应受管路径。移动后的目录绑定变化通过原描述符尝试排他移回，保留新目录中的外来文件；回退受阻仍保留现场。
- 父目录变化写入操作日志的目录身份检查，保持 `needs_attention`。显式恢复也必须先确认原父目录身份恢复，不能因为当前路径下找不到 partial 就宣称恢复成功。恢复原目录后，只清理由本事务确认归属的暂存文件。
- 不执行历史 SQL，不对旧 Windows 库开放写入，不通过新路径覆盖外来替换文件。

## 验证

`test_replacement_boundaries.py` 新增 4 项先失败后通过：

1. guard 后、SQLite 打开前换入外来数据库，直接 DML 被拒绝，外来数据库字节不变。
2. SQL 已执行、提交前替换数据库，事务回滚；恢复原数据库后没有未提交活动。
3. rename 系统调用间替换目标父目录，原描述符移回自有文件；新父目录中的外来文件保留。
4. 复制中替换父目录，原来源和外来目标保留，操作进入待检查；目录未恢复时拒绝清掉状态，恢复原目录后清理自有 partial，外来文件仍保留。恢复扩展断言曾失败，修正后通过。

新增客户端断连用例通过：首个进度后关闭 stdin/stdout，后台结束并释放库锁；已完成组的内容完整，来源字节不变，无未完成事务。CPython 可能在最终 stdout flush 遇到断管时返回 120，此用例验证文件和锁状态，不将该退出码误判为数据损坏。

受影响检查：6 个文件原语用例、2 个 SQL 失败/原子活动用例，以及现有 SIGINT 组间取消和暂存身份后崩溃恢复用例通过。没有重跑人物规则、界面和其他稳定业务套件。

Debug/Release 构建成功；两个 app 内的 catalog.py、safeos.py、fileops.py 摘要均与当前源文件一致，deep strict 签名检查通过。没有修改 Reference/Windows。

## 范围

这组证据针对列出的确定时序，不是任意对抗性反复置换的原子 SQLite VFS 保证。真实跨卷/卷重挂、真实外置介质和断电、初始化与清理的剩余故障场景仍待继续；没有据此宣称整个文件引擎全部验收。
