# 整库系统废纸篓验证

2026-11-04 晚，Apple Silicon / arm64；接入 P6 的整库回收，使用 macOS FileManager.trashItem，不提供永久删除回退。

## 流程

只对当前已打开且可写的本机库提供入口。先统计库名、路径、照片数（含应用回收站）、总文件数及逻辑字节数；用户必须输入匹配的名称才能确认。回收的是整个目录，包括库内其他文件。

私有后台保存单次预览 token，重新检查来源重叠、应用路径、嵌套照片库、链接/特殊文件、库身份和目录树指纹。来源检查覆盖大小写路径别名；确认时使用最新来源保护集合。目录身份/成员及文件身份/大小/mtime 纳入指纹；数据库和 WAL 受校验，派生 SHM 索引的读取变化不误判为用户内容变化。

Swift 持有预览目录的描述符，拒绝预览后目录或数据库被替换。系统文件协调区间内，串行后台 actor 先复核预览，再执行系统回收，期间不接受其他后台请求。库生命周期锁一直保留至回收结束；成功后关闭后台会话、移除最近入口并清空当前库。失败时保留库/会话及错误，不调用永久删除。最终回收期间禁止新选来源和取消操作；统计阶段仍可取消。

## 边界与剩余范围

文件协调与持有描述符覆盖本应用串行操作及协作应用；不宣称抵御不遵守文件协调的恶意同用户进程在最终系统 API 调用窗口内持续替换命名空间。真实外置卷/跨卷、其他更多文件引擎故障验收、人物自动分类、框选边缘滚动和交互性能、运行时许可及最终独立打包仍需推进。

测试仅写自建临时目录或 build/fixtures；Windows 参考及用户来源只读，不推送、不发布。Windows 互通/旧库转换继续按用户要求暂缓。
