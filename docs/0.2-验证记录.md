# 0.2 修复验证记录

对应2026-10-28用户反馈，保留原照片库和SD源文件。

- 读取取消：逐文件枚举和逐张EXIF读取都检查取消，取消任务不发布部分扫描；UI保留原来源、选片和目录位置。
- 框选：200张测试网格，起拖统一缓存卡片几何位置，后续按帧使用缓存，增量更新选中样式；保留边缘滚动和Esc取消。
- 缩略图：JPEG解码前降采样，不同照片真正并发，相同在途请求合并；完成请求会重新经过后台文件指纹检查。10张生成的6000×4000 JPEG、开发磁盘冷缓存最终记录：旧版2.302秒、新版0.691秒。不是实际SD卡或真实相机性能承诺。
- 子文件夹：默认逐层浏览和左侧切换，显式“全部子文件夹”才混合展示；SD跨目录选片保留。
- 成片：JPEG可直接标为成片；可取消全部或解除单个版本。原片与修图阶段保留，复制文件移入`.片集/取消关联保留`，没有删除文件。RAW仅在导出图片后关联。
- 操作范围：成片视图隐藏原片阶段按钮；人物/活动/阶段切换清空旧库选择，批量操作只取当前可见选中照片。
- 导入：未设照片库时自动弹出原生目录选择器，可以选目录或新建文件夹；取消则不导入、不丢选片。
- 交互：单击切换选择/取消，双击只预览且恢复双击前选中状态；Shift范围选择保留。

验证过程：对应取消、JPEG缩略图并发与降采样、成片标记/取消/单版本解除/占用回滚等回归先失败，再通过。使用真实Python后台的测试和真实UI模块的浏览器交互测试分别验证，浏览器测试桥接不冒充真实磁盘操作。

独立审查发现3项Important及2项过滤边界问题，均已补充失败回归并修复：缓存清理不能删除使用中的图片；读取缓存时保存响应内容，防止后续清理影响返回；更新访问时间不会重建空缓存；前端仅合并在途请求，PS保存后重新查看会验证文件版本；“只看已选”过滤同步当前照片和检查器；双击不会丢失另一张照片的取消选择；切换人物和活动重置“只看已选”。这些边界均属于本次用户反馈范围，未延后。

最终Windows联调另复现了程序自己的预览文件句柄阻止取消关联。通过文件读写协调修复：不同照片可并发读预览，文件日志事务在移动前等待这些读取结束。对应等待与并行两项回归验证，避免用全局串行加载换取移动安全。

最终：50项Python测试（含便携包清单）通过，3组真实UI模块浏览器检查通过，覆盖200张框选/双击/缩放、目录和导入、外部保存和过滤边界。测试中的PS保存由可变图片响应模拟，未启动用户Photoshop。

原生WebView2窗口通过实际界面点击和真实后台完成：SD两个子目录分别浏览与跨目录选片、首次导入自动选择库、JPEG/RAW/XMP复制、直接成片/取消成片、关联导出图片和解除关联。原片路径有效、SD源文件SHA-256不变。原生系统选择窗口在自动测试中替换为明确指定的临时目录，不读取用户磁盘。

真实SD卡吞吐与真实S5M2 RAW、Photoshop保存通知仍需用户设备联调；没有把生成JPEG或伪RAW文件操作夹具当成相机验证。现有0.1数据库通过兼容建表方式增加取消关联保留记录，不改写SD卡、无需迁移照片库到新目录。
