# 片集 0.4 修复与交互计划

规格：用户本轮五项反馈及全局选择规范。使用 systematic-debugging、writing-plans、test-driven-development，延续现有 feature/photo-manager 仓库内联实现。

## 根因与交付

1. 真实日志中两种格式都在 discovery.py 的 Path.is_symlink/lstat 因 WinError 1392 抛错，终止整个扫描。逐文件和子目录隔离读取异常；目录枚举错误也进入报告；读取前支持 both/jpeg/raw；报告保留路径、阶段和系统错误码。可读结果照常发布，完全失败保留前次扫描，取消不发布。仅做只读扫描，不修复/写入用户 SD 卡。
2. 活动目前只有导入时隐式创建，没有显式 API/按钮；导入字段缺少清楚的“已有/新建”操作。新增严格去重的 create_activity，导入中可直接新建并选中，总界面增加创建入口及活动右键。
3. 人物侧栏可折叠并支持右键新建、重命名、删除。删除分类将照片移回待分类而非删除照片；活动内合照/待分类固定类别受保护。删除失败及取消后分类仍有效，回收站中的照片也更新到待分类。
4. 全部人物默认展示人物文件夹；双击人物进入其子文件夹（选出原片/已修原片/成片），双击子文件夹进入照片；提供“平铺照片”入口及面包屑。SD 文件夹同样改成单击选择、多选/取消，双击进入。可折叠人物列表保留当前过滤范围。
5. 统一选择协议：所有列表/网格项目单击切换可多选、双击进入或预览且不改变双击前选择；右键已选组保留多选，未选项右键只选择该项。导航标签、执行按钮和单值表单控件仍按其控制语义操作。侧栏活动与人物可选择多项，双击打开单项；选中人物可批量删除分类。

## 审查重点

- 1392 不再拖垮其他文件，且错误不静默吞掉；完全不可读不能当作零照片成功。
- 创建活动实际建立库内目录，重复名称/保留名称不误建；导入途中创建活动不丢 SD 选片。
- 删除人物不删除照片，不悬空回收站照片的人物归属；出错/取消不能丢分类入口。
- 文件夹双击不改变此前选择；退出/切活动/切库不会把旧范围选择带入批量操作。
- 折叠仅控制显示，不改变人物归属；全部人物目录与平铺能切换，日期/格式筛选在文件夹统计中一致。

## 裁决与记录

Ruling: 删除人物分类=将活动中的照片移回待分类后移除普通人物记录 — 用户要求删除人物但未要求删除其照片 — 保留人物目录中的未管理文件，不递归删除目录。
Ruling: 侧栏列表采用选择与打开分离，导航/表单不是可多选文件对象 — 遵守用户所有可选项目的统一交互，同时保持菜单与按钮可操作 — 增加双击进入提示。
