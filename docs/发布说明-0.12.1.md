# LUMIX 洗衣机管理器 · 0.12.1 更新日志

发布日期：2026 年 11 月 3 日  
平台：Windows 11  
交付状态：正式版（Windows 11）

本次更新重点修复文件夹缩略图的缩放比例与连续调整卡顿，并完成 0.12 阶段的模块化整理。近期版本还持续改进了深色玻璃材质、导航反馈、照片预览，以及窗口和文件夹的开合动画。

## 一、0.12.1：缩略图缩放修复

- **文件夹封面保持 4:3。** 修复小尺寸下封面被挤成长条、放大后比例不自然的问题；文件夹名称最多显示两行，悬停可查看完整名称。
- **卡片大小跟随滑杆。** 修复网格把剩余空间分摊给卡片，导致切换列数时突然变宽的问题。窗口较窄时，卡片限制在可用宽度内。
- **连续调整更及时。** 滑杆即时反馈，将同一显示帧内的多次输入合并为一次网格尺寸更新，减少重复写入与样式计算；设置保存继续合并处理。
- 保留 80–720 调整范围、加减按钮、Ctrl + 滚轮和当前选择；文件夹进入、返回动画沿用 0.12。

## 二、近期累计改进：材质、交互与动效

以下为 0.8–0.12 阶段的累计成果，0.12.1 继续保留。

### 深色玻璃与连续导航

- 当前采用深色侧栏和控件，侧栏轻微承接照片色彩，照片工作区保持中性深色。
- 悬浮操作栏、阶段切换和弹窗使用分层玻璃材质，文字、图标与照片前景保持清晰。
- 修复“选片／照片库”切换缺少可见动画的问题；导航高光连续移动，快速反向操作从当前位置继续。
- 人物列表展开、收起和阶段切换提供连续反馈；操作立即生效，不等待动画结束。

### 照片预览与选片

- 滚轮围绕鼠标指向的位置缩放，拖动图片可平移查看细节。
- 左右方向键切换照片，每张照片重新适应窗口，先展示完整构图。
- 预览中使用空格或选择按钮切换选择，关闭后保留结果；双击预览本身不改变已有选择。
- 快速切图时，迟到的图片或详情结果不会覆盖当前照片。

### 窗口、弹窗与文件夹开合

- 主窗口就绪后淡入，关闭时短促淡出，再完成任务清理和库锁释放；重复关闭只清理一次。
- 应用内弹窗从触发位置展开，关闭沿反向路径收回；关闭后的动画表面不阻挡后续操作。
- 人物与来源文件夹从实际卡片展开到照片区，返回时恢复滚动位置并收回对应文件夹。
- 快速进入、返回或切换导航时，以最新操作为准；键盘、减少动态及浏览器能力不足时直接切换。
- Windows 原生文件选择窗口遵循系统行为。玻璃效果由 WebView2 实现，应用沿用现有 Windows 技术栈。

## 三、架构更新：按功能拆分，统一管理状态与文件操作

此次整理将集中在入口文件中的业务职责迁到对应模块。后续修改某项功能，可以先定位该功能的控制器、服务和回归检查，减少跨功能修改的范围。

### 1. 前端：组合入口、功能模块与共享基础分层

`ui/app.js` 收敛为应用启动、模块装配和共享刷新入口：创建任务、详情、侧栏及工作区控制器，并传入必要回调。业务模块不反向依赖 `app.js`。

| 模块位置 | 负责内容 |
|---|---|
| `ui/features/tasks.js` | 来源读取、任务进度、取消及完成后的衔接 |
| `ui/features/sidebar.js` | 活动、人物、来源导航，以及面包屑和侧栏管理 |
| `ui/features/workspace.js` | 主工作区渲染、阶段筛选、工具栏和批量命令 |
| `ui/features/inspector.js` | 照片详情、相机参数、Photoshop 操作与成片关联 |
| `ui/features/*-dialogs.js` | 按导入、人物、回收站等业务分别组织弹窗 |
| `ui/core/` | 状态工厂、纯查询、DOM 工具和共享弹窗原语 |
| `ui/viewer.js`、`selection.js`、`gallery.js` | 预览、选择与网格等专用交互 |
| `ui/thumbnail-size.js`、`gallery.css` | 缩略图尺寸调度、卡片与文件夹几何布局 |

`store.js` 保留为兼容入口，只创建一次应用状态，各模块共享当前活动、人物、筛选与选择结果。筛选和可见项目计算迁入纯查询模块，可以脱离页面单独验证。`dialogs.js` 保留兼容转导出，具体实现归属各自业务模块。

任务 ID 和待扫描来源由任务控制器持有；详情请求版本由详情控制器持有。异步结果归属更明确，取消、失败和快速切换时也有对应的恢复与过期结果处理路径。

### 2. 后端：业务服务拆分，复用已有照片库上下文

后端新增按职责组织的 `services/`，将业务实现从集中式方法中拆出：

| 服务 | 负责内容 |
|---|---|
| `imports.py` | 照片导入、关联补充与导入结果 |
| `people.py` | 人物分类与相关调整 |
| `exports.py` | 成片关联与版本管理 |
| `trash.py` | 回收站业务 |
| `activities.py` | 活动管理 |
| `source.py` | 只读来源扫描与扫描结果发布 |
| `photo_reads.py` | 预览和 EXIF 详情读取 |

修改照片库的服务接收现有 `Library` 上下文，继续使用同一套数据库、文件日志和锁。`Library` 统一持有库根锁、线程锁、`Catalog`、`FileJournal`、目录分配、批处理和恢复机制，避免不同业务各自维护文件事务。

`Bridge` 继续管理网页与本机之间的公开接口、来源授权、当前照片库、扫描注册表、设置、后台任务及预览线程池。业务服务的拆分不会额外向网页暴露文件操作接口。

来源扫描只读，取消时不发布新扫描；照片库中的预览和详情读取继续遵守既有读锁与路径校验规则。永久删除、整库删除和空目录清理仍由原专用模块维护各自边界。

### 3. 动效与业务流程分别维护

导航、玻璃光学、预览、主窗口开合和文件夹转场分别由对应模块维护。文件夹转场使用一次性匹配快照，业务流程负责实际导航、历史和选择结果；动画支持取消、反向衔接及能力回退。

这样，调整动画曲线或材质时，可以更集中地修改表现层；修改导入、人物或回收站时，则从对应业务模块与回归检查开始。

### 4. 开发、测试与打包一起整理

- 新增代码地图，建立“功能 → 前端模块 → 后端服务 → 验证文件”的对应关系。
- 测试输出归入当前项目，默认构建产物在 `dist/`，临时构建文件在 `build/`，源码运行与构建不再依赖旧工作区布局。
- 新增 JS、CSS 和嵌套模块随便携包递归交付，并通过资源与源码逐字节比较检查，减少漏文件或混入旧资源的问题。

技术栈继续为 **Python + 原生 JavaScript + pywebview / Edge WebView2**。既有公开桥接方法、照片库 `.片集` 格式和兼容路径保留，现有照片库可继续打开；模块化整理阶段保持 0.12 的外观与操作行为。

## 四、交互与文件管理规则

- 侧栏活动、人物、来源目录单击直接进入；主区照片、文件夹与回收站列表单击选择或取消，支持多选，双击进入或预览。
- 全选、取消全选和 Ctrl + A 仅作用于当前可见项目。
- SD 来源保持只读，导入只复制；单个读取错误隔离处理，并显示具体路径与系统错误码。
- 删除人物分类时，原片与关联成片移回同活动待分类；照片删除先进入应用回收站，永久删除需要单独确认。
- 整库删除仍是独立操作，经库名确认后交由 Windows 系统回收站处理。
