# 0.12.1 缩略图尺寸验证

本轮修复用户明确指出的“拖动缩略图滑杆时，文件夹大小变化卡顿、比例奇怪”。未修改双击进入/返回文件夹的转场逻辑。

## 原因和修改

- 原封面固定高 135px，80px 小卡片里封面只有约49px宽；放大后则变成横向扁条。新封面固定4:3，名称保留两行高度，长名称完整内容可悬停查看。
- 原网格的 `1fr` 会把剩余宽度分给卡片，列数变化时尺寸突跳。现在卡片遵循80–720目标宽度，超出窄窗口可用宽度时收敛到窗口，余量留在右侧，滚动条保留稳定空间。
- 原尺寸CSS变量会继承到全部缩略图后代；新变量只作用于网格。200个人物文件夹、每人3张示例的60次连续尺寸压力记录中，样式重算由约365ms降至约20ms。比例布局会增加布局计算，故不将样式耗时降幅等同于整体帧率提升。最后单独回归记录无超过32ms的帧间隔；不同设备与真实图片解码仍会影响实际流畅度。
- 新 `thumbnail-size.js` 把多次输入合并到一个显示帧；100次密集输入只产生一次网格尺寸写入，最后值和500ms合并保存保留。控件即时更新，不排队播放尺寸动画。
- 新 `gallery.css` 集中管理网格和文件夹几何，保留原选择和打开规则。

## 验证

- 新浏览器回归先在旧实现中复现：封面比例错误、密集更新99–100次写入、窄窗口比例错误；修复后通过。
- `npm test`：17/17组通过，包括新增尺寸回归、原选片、多选、预览、缩略图范围、目录转场和玻璃动效。
- 新实包 PyInstaller 构建成功；指定新包运行完整 `pytest -q`：109项全部通过，包含新增JS/CSS资源与源码字节一致性检查。
- 真实WebView2加载新包内UI，22个人物文件夹、33个滑杆尺寸（80至720、间隔20）均满足4:3，测得最大比例误差0；卡片实际宽度跟随滑杆。100次密集更新最终值正确，1040×720下无横向溢出，选择与保存结果保留，全部测试来源SHA-256不变。
- 所有文件操作只发生在自建临时库；未读取或更改用户照片库/SD卡。本轮未进行Photoshop实际保存联调。

日志位于 `.superpowers/resize-full-ui.log`、`.superpowers/thumbnail-final.log`、`.superpowers/resize-build.log`、`.superpowers/resize-native.log`；尺寸与性能样本位于 `.superpowers/ui-artifacts/thumbnail-resize-before.json` / `thumbnail-resize-after.json`。
