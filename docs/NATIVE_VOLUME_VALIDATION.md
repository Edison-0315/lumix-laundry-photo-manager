# 卷身份与跨卷验证

2026-11-05，Apple Silicon，macOS 27.2。仅使用 build/fixtures 下自建的两个 128 MB APFS sparseimage；未对真实外置盘或用户库执行写入。映像现已卸载。

## 修复

设备号 st_dev 是本次挂载的标识，重新挂载可变化。此前本机库及持久化文件回执将它作为永久身份，导致同一库在同一路径重新挂载后无法写入。

新建库标记增加卷 UUID，文件操作/回收站/永久删除回执记录卷 UUID 与 inode。打开库仍要求原路径、卷 UUID、目录和数据库 inode 一致。已打开会话继续校验当前设备号，并检查卷 UUID，防止设备号被另一卷复用。Swift 整库回收接口保留原数值身份格式。

没有卷 UUID 的旧本机标记不自动修改；同设备仍可打开，设备号变化后保守拒绝。旧数值文件回执同样只接受原设备号。Windows 库不转换、不写入。

## 证据

- 5 个新增单元用例：同卷换设备号、不同卷/替换 inode 拒绝、持久化回执与 Swift 接口、旧标记只读保持、活动会话卷替换保护。
- 身份格式修改后，文件操作、回收站、替换边界及库管理相关 24 个用例通过；最后增加活动会话卷检查后，受影响的 13 个用例通过。不重复来源、模型、界面和性能套件。
- 主机来源 → 映像库、映像来源 → 主机库均完成复制导入及人物移动；真正跨设备 rename 返回 EXDEV，原文件保留。
- 交换两个映像的挂载顺序，库设备号由 16777243 变为 16777239。仍可打开新标记库、恢复挂载前留下的已记录 partial、依据挂载前回收站回执永久删除测试照片，并继续导入。来源 SHA-256 和 mtime 未变化。
- 重挂载验收脚本：macos/BackendTests/validate_volume_remount.py。仅接受专属 StableLibrary 夹具及 stable-receipt.json；已完成的夹具禁止重复执行，需重新准备。结果保留在忽略目录 build/fixtures/CrossVolumeValidation/stable-result.json。
- Debug/Release 后台资源摘要与源文件一致，codesign --verify --deep --strict 均通过。

此证据覆盖 APFS 磁盘映像，不代表真实 USB/网络/exFAT 卷或突然断电验收。未提供稳定卷 UUID 的文件系统会明确拒绝可写库，不降低身份检查。移动库到新路径仍未实现。
